# Weather Pulse

Weather forecast, geomagnetic storms, weather maps and a public holiday calendar for any location.
Static site hosted on **GitHub Pages**.

## Live site

👉 [https://weatherpulse.eu/](https://weatherpulse.eu/)

Change the script or its data file and run it again; changes made directly in the generated HTML are overwritten.

Languages: Bulgarian, English, German, Italian, Spanish (switcher in the header, saved in the browser).

**How pages are translated.** The generated pages exist once per language, each at its own URL: Bulgarian at the root (`/luna/`),
the others under a prefix (`/en/luna/`, `/de/luna/`, `/it/luna/`, `/es/luna/`); `/europe/` too (`/en/europe/` ...). Every page has `<link rel="alternate" hreflang>` for the languages in which it is indexed and `x-default`; the language
switcher opens the translation of the same page, and a visitor who chose another language is sent from the root URL to it
(`page()` in `build-pages.js`, `language-selector.js`). Links to the home page and `/magnitni-buri/` follow the language of the page too: `page()` rewrites them in the generated pages, `localPages` in `js/mobile-nav.js` in the pages translated in the browser. City names in `/europe/` come from `europe-data.js` (English) and `europe-names.js`; country names from `Intl.DisplayNames`.
**Which translations are indexed** (`places.js`): city pages in German, Italian and Spanish only for the countries of the language and the big tourist places; the others exist (the language switcher finds them in `data-alt` on `<html>`) but are `noindex, follow`, have no hreflang and are not in the sitemap.
The home page and `/magnitni-buri/` are written by hand in Bulgarian and get their own translated pages from `build-main.js` (`/en/`, `/en/magnitni-buri/` ...): run it after changing either page or its texts. They link with root paths (`/weather/`, `/css/...`), never relative ones, because the same HTML is also served from `/en/`.
The forecast, maps and holiday calendar pages get translated addresses from `build-main.js` too (`/en/weather/` ...), with the title, description, heading and menu in the HTML; the rest of the page is still translated by its scripts from their dictionaries. Like home and storms, they must link with root paths. `/contacts/` is translated only in the browser.
A first-time visitor whose browser is in another language is sent from the Bulgarian page to the translation by a script in the page head (robots are not).

**Country context.** `js/place-context.js` reads the place the visitor picked on the forecast page (`lastLocation`; Sofia on a first visit).
The home page cities block (`js/home-cities.js`) then lists the main cities of that country (`js/destinations.json`), and `/nebeto/` (`js/sky-local.js`,
`js/aurora-kp.js`) shows times in the time zone of the place, a country picker, and eclipse and northern lights texts for that latitude instead of the Bulgarian ones. The Moon calendar pages (`js/luna-local.js`, `js/luna-today.js`) rebuild their phase tables and day tables from `js/moon.js` in that time zone.
The generated HTML stays written for Bulgaria; the scripts only replace it for other countries.

**Adding or changing text:** every generator takes its text from a `text-*.js` file (or `sky-events.json`) that has the same keys in all five
languages; change all five together. A new language needs its code in `i18n.js` and a text block in each of those files.

## Scripts

All scripts are in `.github/scripts/` and are run from the repository root with Node 20.

| Script | What it does |
|--------|--------------|
| `node .github/scripts/build-pages.js` | Writes the city, hub and holiday pages (all languages) and the sources page |
| `node .github/scripts/build-main.js` | Writes the translated home, storms, forecast, maps and holiday pages (`/en/`, `/de/magnitni-buri/`, `/it/weather/` ...) from the Bulgarian ones; stops if a text is missing or Bulgarian text is left in a fully translated page |
| `node .github/scripts/build-forecast.js [folder ...]` | Writes today's 7-day forecast (median of the three models, as on the site) into the HTML of the city pages and a sentence about the days (warmest, coldest, rain, compared with the climate). Without arguments: all city pages (`/vremeto/` and `/europe/`) in all languages, about 1060 pages. Run it after `build-pages.js`, which writes the pages with a "Loading…" line |
| `node .github/scripts/build-storms.js` | Writes NOAA's 3-day forecast of magnetic storms (highest Kp and level per day) into `/magnitni-buri/` and its translations, between two comment marks in `#stormForecast`, keeps the data in `storms-data.json` and writes the Bulgarian storm pages. `build-main.js` keeps the table when it rewrites the translations |
| `node .github/scripts/build-static.js` | Writes the About and Privacy pages (all languages) |
| `node .github/scripts/build-europe.js` | Writes the Europe pages (all languages) |
| `node .github/scripts/build-luna.js [year] [--sitemap]` | Writes the Moon calendar pages (the year and the next one) |
| `node .github/scripts/build-nebeto.js [--sitemap]` | Writes `/nebeto/` from `sky-events.json`; add next year's events there every autumn (IMO calendar for meteors) |
| `node .github/scripts/test-moon.js` | Checks `js/moon.js` against USNO phase times (`moon-reference.json`) |
| `node .github/scripts/test-sun.js` | Checks `sun.js` (sunrise/sunset on the city pages) against Open-Meteo (`sun-reference.json`) |
| `node .github/scripts/build-climate.js [--europe]` | Refreshes `climate.json` (monthly climate from the ERA5 archive); rarely needed. `--europe` does the cities of the Europe pages into `climate-europe.json` (about 25 minutes; an interrupted run continues) |
| `node .github/scripts/build-destinations.js [GR,CZ]` | Refreshes `js/destinations.json`, the one-tap city buttons under the search |
| `node .github/scripts/build-sitemap.js [--seed]` | Writes `sitemap.xml` from the pages that exist (no redirects, no noindex). `<lastmod>` changes only when a page's content changes (hashes in `sitemap-hashes.json`; the daily forecast is left out). Run it after any generator |
| `node .github/scripts/build-extra.js` | Writes `/gradove/`, the 10-day and weekend pages, the regional pages, the days off and `/uidzhet/` |
| `node .github/scripts/build-redirects.js` | Writes the redirect pages of moved addresses |
| `node .github/scripts/build-storm-pages.js` | Writes the Bulgarian storm pages from `storms-data.json` (`build-storms.js` runs it) |
| `node .github/scripts/check-site.js` | Checks for missing local files, JavaScript/JSON syntax errors (the generators too), that every page's canonical and og:url are its own address, that the translations of a page list each other in `hreflang`, and that `sitemap.xml` lists exactly the pages that exist |
| `node .github/scripts/indexnow.js` | Sends the pages in `sitemap.xml` to IndexNow search engines |

Static assets use a version in the URL (`theme.css?v=N`). When a stylesheet or script changes, raise its version in the page templates (`VERSION` in `build-pages.js`) and regenerate.

## GitHub Actions

- **Site check** (`check.yml`): runs `check-site.js` on every pull request and push to `main`.
- **Moon calendar** (`luna-yearly.yml`): on 1 December builds the next year's `/luna/` pages and opens a pull request (an issue if Actions may not open PRs). Pull requests opened by Actions do not start the Site check; run it by hand.
- **Daily forecast** (`forecast-daily.yml`): every morning (03:20 UTC) runs `build-forecast.js` and `build-storms.js` and commits the city pages and `sitemap.xml` to `main` as `github-actions[bot]`, then asks Pages to publish. Also runs when the city pages change on `main`. In the browser `js/city-forecast.js` replaces the written forecast with the live one. Pull `main` before working: it gets one commit a day.
- **IndexNow** (`indexnow.yml`): after pushes to `main` that change HTML or the sitemap, waits for Pages to publish and notifies Bing and others. Do not delete the key file `fd0de53b5adf000adbdcd0dff74d4364.txt` in the root: it proves the site is ours.

## Data sources

No API keys are needed. All services below are free and called directly from the browser.

- [Open-Meteo](https://open-meteo.com/): forecast (default "best match" blend of ICON, ECMWF IFS, GFS and Météo-France), ensemble for reliability, ERA5 archive for climate, geocoding
- [NOAA SWPC](https://www.swpc.noaa.gov/): geomagnetic Kp index
- [OpenStreetMap Nominatim](https://nominatim.openstreetmap.org/): reverse geocoding and country lookup
- [Windy](https://www.windy.com/): embedded weather maps
- [Nager.Date](https://date.nager.at/): public holidays

## Offline mode

The site is an installable PWA (`manifest.webmanifest`). `sw.js` caches the main pages for offline use (network first, so a deploy shows at once; the last 60 visited pages are kept) and serves scripts and styles with `?v=N` from the cache first, so **a changed `.js`/`.css` file must get a new `?v=`** or visitors keep the old one. Add new top-level pages to the `PAGES` list in `sw.js` if they should work offline, and bump `CACHE` when cached files change in a way visitors must pick up.

## Hosting

GitHub Pages serves the `main` branch from the repository root. The custom domain is set in `CNAME`.

- `404.html` is shown for missing pages.
- `cookie-consent.js` shows the cookie banner and loads Google Analytics only after the visitor accepts.
- `.htaccess` and PHP do not work on GitHub Pages, so redirects and server-side code are not used.

## Adding a page

1. Create it (or add it to the generator and run the script).
2. Run `node .github/scripts/build-sitemap.js`.
3. Add it to `sw.js` if it should work offline.
4. Run `node .github/scripts/check-site.js`.
